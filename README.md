# zope 🐟

## ✨ Ключевые возможности

*   **Поддержка Multi-Target:** Управляйте десятками изолированных харнессов в рамках одного проекта без путаницы в папках.
*   **Мультиязычность из коробки:** Единый интерфейс для работы с C/C++ (AFL++, libFuzzer), Python (Atheris), Java (Jazzer) и .NET/C# (SharpFuzz).
*   **Умные критерии остановки (Smart Stop):** Автоматическое завершение сессии, если новые пути (paths) не находились заданное время, или при достижении лимита покрытия.
*   **Git-like CLI:** Привычный UX (`zope init`, `zope start`, `zope status`).

## 📂 Структура проекта после `zope init`

Инструмент изолирует все артефакты внутри скрытой директории `.zope/`, не загрязняя ваш основной репозиторий:

```text
my_project/
├── .zope/                  # Системная папка (автоматически добавляется в .gitignore)
│   ├── targets/            # Изолированные данные по каждой цели
│   │   ├── target_auth/    
│   │   │   ├── bin/        # Бинарники (target_asan, target_cov)
│   │   │   ├── corpus/     # Накопленный (current) и начальный (seed) корпус
│   │   │   ├── crashes/    # Уникальные краши + ASan стектрейсы (.txt)
│   │   │   └── stats/      # Сырые логи движков
│   └── reports/            # Сгенерированные HTML-отчеты
├── zope.toml               # Главный конфигурационный файл проекта
└── ...                     # Ваши харнессы и их зависимости
```
Детально структура проекта описана [здесь](docs\PROJECT_STRUCTURE.md).

## ⚙️ Конфигурация (`zope.toml`)

Пример настройки проекта с несколькими целями на разных языках:

```toml
[project]
name = "secure_enterprise_app"

# Цель №1: C++ Харнесс для закрытой библиотеки (Движок AFL++)
[[target]]
name = "cpp_auth_api"
language = "cpp"
engine = "afl++"
source = "harness_auth.cc"
link_flags = "-L. -lsecret"
sanitizers = ["address", "undefined"]

# Умные критерии остановки для этой цели
[target.stop_conditions]
max_time_since_last_path = "2h"  # Остановить, если 2 часа нет новых путей
min_coverage_pct = 95.0          # Остановить при достижении 95% покрытия

# Цель №2: Проверка парсера на Python (Движок Atheris)
[[target]]
name = "py_json_parser"
language = "python"
engine = "atheris"
source = "fuzz_json.py"
```
Детально возможности конфигурации описаны [здесь](docs\CONFIGURATION.md).

## 🛠 Сценарий работы (CLI)

### 1. Инициализация
Создает в рабочей директории проект zope-fuzz.
```bash
zope init
```

### 2. Сборка целей
Автоматически компилирует харнессы на основании zope.toml с нужными санитайзерами и флагами профилирования для покрытия.
```bash
zope build --all
```

### 3. Запуск фаззинга
Запускает фаззинг конкретной цели, автоматически распределяя процессы по ядрам. По умолчанию задействуется только одно ядро.
```bash
zope start cpp_auth_api             # фаззинг с использованием одного ядра
zope start cpp_auth_api --jobs 4    # фаззинг с использованием 4 ядер
```

### 4. Мониторинг в реальном времени
Выводит краткий читаемый дашборд по состоянию всех целей фаззинга.
```bash
zope status
```

### 5. Генерация отчетов
Берет накопленный корпус, быстро прогоняет его через бинарник разметки покрытия и выдает красивый HTML-отчет.
```bash
zope report --html
zope report --markdown
```
