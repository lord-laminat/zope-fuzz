# ⚙️ Справочник конфигурации (zope.toml)

Настоящий документ содержит полное описание структуры конфигурационного файла `zope.toml`, типов данных, правил валидации и параметров рантайма. Файл используется ядром `zope` для сборки контейнеров, компиляции харнессов и управления сессиями фаззинга.

---

## 🌳 Общая структура файла

Файл `zope.toml` состоит из трех основных блоков:
1.  `[project]` — глобальные метаданные проекта.
2.  `[runtime]` — конфигурация среды выполнения (хост или контейнеры).
3.  `[[target]]` — массив таблиц (структур), описывающих отдельные цели фаззинга.

---

## 1. Глобальные секции

### Секция `[project]`
Определяет общие свойства фаззинг-проекта.

| Параметр | Тип данных (Go) | Обязательный | Описание и пример |
| :--- | :--- | :--- | :--- |
| `name` | `string` | **Да** | Уникальное имя проекта в нижнем регистре. Используется как префикс для именования Docker-образов. <br>`name = "secure_gateway"` |

### Секция `[runtime]`
Определяет, где и как будут собираться и запускаться сессии фаззинга.

| Параметр | Тип данных (Go) | Обязательный | Дефолт | Описание и пример |
| :--- | :--- | :--- | :--- | :--- |
| `engine` | `string` | Нет | `"host"` | Среда исполнения. Варианты: `"host"` (локально), `"docker"`. |
| `runtime_image` | `string` | Нет (для docker) | `"zope_runtime:latest"` | Базовый Docker-образ, содержащий `zope` CLI и предустановленный LLVM-тулчейн. |

---

## 2. Секция переиспользования `[defaults]`

Позволяет избежать дублирования конфигурации для проектов с десятками целей. Заданные здесь параметры автоматически применяются к каждой цели из массива `[[target]]`, если эта цель не переопределяет их явно.

| Параметр | Тип данных (Go) | Обязательный | Описание |
| :--- | :--- | :--- | :--- |
| `language` | `string` | Нет | Язык программирования по умолчанию для всех харнессов. |
| `engine` | `string` | Нет | Фаззинг-движок по умолчанию. |
| `compile_flags` | `string` | Нет | Глобальные флаги компилятора (например, уровни оптимизации `-O2`). |
| `link_flags` | `string` | Нет | Глобальные флаги линковщика для внешних зависимостей. |
| `sanitizers` | `[]string` | Нет | Список санитайзеров, подключаемых ко всем собираемым целям. |

Внутри `[defaults]` также доступна подколекция **`[defaults.stop_conditions]`**. Параметры `Smart Stop` из этой секции станут базовыми правилами остановки для каждого запущенного фаззера.

---

## 2. Секция целей `[[target]]` (Массив)

Каждая цель описывается независимым блоком `[[target]]`. Вы можете объявить неограниченное количество целей для разных языков в одном файле.

### Основные параметры цели

| Параметр | Тип данных (Go) | Обязательный | Допустимые значения / Описание |
| :--- | :--- | :--- | :--- |
| `name` | `string` | **Да** | Уникальное имя цели (идентификатор для CLI). Разрешены: `a-z`, `0-9`, `_`. |
| `language` | `string` | **Да** | Язык программирования цели. <br>Варианты: `"cpp"` (или `"c"`), `"python"`, `"java"`, `"csharp"`. |
| `engine` | `string` | **Да** | Фаззинг-движок. <br>Варианты: `"afl++"`, `"libfuzzer"`, `"atheris"`, `"jazzer"`, `"sharpfuzz"`. |
| `source` | `string` | **Да** | Путь к файлу харнесса относительно корня проекта. |
| `image` | `string` | Нет | Переопределение Docker-образа для конкретной цели (сборка харнесса с зависимостями). |

### Параметры сборки C/C++ (применимо для `language = "cpp"`)

| Параметр | Тип данных (Go) | Обязательный | Описание и пример |
| :--- | :--- | :--- | :--- |
| `compile_flags`| `string` | Нет | Дополнительные флаги компилятора (C/CXXFLAGS). <br>`compile_flags = "-O2 -I./include"` |
| `link_flags` | `string` | Нет | Флаги линковщика (LDFLAGS). <br>`link_flags = "-L. -lsecret"` |
| `sanitizers` | `[]string` | Нет | Список подключаемых санитайзеров компилятора. <br>Варианты: `"address"`, `"undefined"`, `"memory"`, `"thread"`. <br>`sanitizers = ["address", "undefined"]` |

---

## 3. Умные критерии остановки `[target.stop_conditions]`

Подколлекция внутри конкретного `[[target]]`. Позволяет автоматически завершать фаззинг при достижении плато или лимитов, экономя ресурсы процессора.

| Параметр | Тип данных (Go) | Обязательный | Формат и правила валидации |
| :--- | :--- | :--- | :--- |
| `max_time_since_last_path` | `string` | Нет | Строковое представление времени (Go `time.Duration`). Останавливает фаззер, если новые пути в коде не находились заданное время. <br>Примеры: `"2h"`, `"45m"`, `"1d"`. |
| `min_coverage_pct` | `float64` | Нет | Процент покрытия кода, при достижении которого цель считается полностью протестированной. <br>Диапазон: `0.1`–`100.0`. `min_coverage_pct = 95.5` |
| `max_total_time` | `string` | Нет | Жесткий лимит на общую продолжительность сессии фаззинга для этой цели. <br>Пример: `max_total_time = "24h"` |

---

## 📋 Комплексный пример валидного `zope.toml`

```toml
[project]
name = "enterprise_platform"

[runtime]
engine = "docker"
base_image = "docker.io/vanilla/zope-runner:v1.2"

# Глобальные настройки для всех C++ целей в проекте
[defaults]
language = "cpp"
engine = "afl++"
compile_flags = "-O3 -DDEBUG_FUZZ"
sanitizers = ["address", "undefined"]

[defaults.stop_conditions]
max_time_since_last_path = "3h"
max_total_time = "12h"

# ---------------------------------------------------------------------
# Цель 1: Наследует всё из [defaults]. Указываем только уникальный source.
# ---------------------------------------------------------------------
[[target]]
name = "cpp_packet_parser"
source = "fuzz/packet_harness.cc"
link_flags = "-lwire_static"

# Переопределяем одно условие останова конкретно для этой сложной цели
[target.stop_conditions]
min_coverage_pct = 98.0

# ---------------------------------------------------------------------
# Цель 2: Полностью переопределяет defaults, так как написана на Python
# ---------------------------------------------------------------------
[[target]]
name = "py_api_auth"
language = "python"
engine = "atheris"
source = "tests/fuzz_api.py"
```
